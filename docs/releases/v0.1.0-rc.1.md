# norm-spec v0.1.0-rc.1

Status: published. `v0.1.0-rc.1` is tagged (signed, verified) at commit
`5c781964`, the GitHub Pre-release with four native archives and checksums is
live, and `norm-spec-core`, `norm-spec`, and `norm-spec-cli` are on crates.io.
This is a release candidate, not stable `v0.1.0`; D017 bound the tag, archives,
and `.cargo_vcs_info.json` to one exact hosted-green commit and treated each
public action as a maintainer checkpoint.

## What this candidate contains

This is the first public-distribution rehearsal for the independent Rust
norm-spec product line. It provides:

- one deterministic Rust semantic engine for A1 parsing, collection, Draft 7
  and profile validation, semantic validation, and scan aggregation;
- the `norm` CLI with `parse`, `collect`, `validate`, `init`, `scan`, and
  machine-readable `compatibility` commands;
- the high-level `norm-spec` Rust facade and lower-level `norm-spec-core` crate;
- the independent `norm-spec-conformance` runner and locked 82-case A1 bundle;
- a canonical framework-neutral Skill that calls the same engine and fails
  closed when it is missing or incompatible;
- self-verifying target-specific archives with source, contract, Skill, and
  checksum identity.

No agent plugin is required for standalone CLI, Rust, conformance, or Skill
adoption. Automatic host injection and enforcement remain downstream adapter
responsibilities.

## Native archives

The candidate supports these natively built and executed archive targets:

| Platform | Rust target |
|---|---|
| Ubuntu 22.04 x86-64 with glibc | `x86_64-unknown-linux-gnu` |
| macOS Apple Silicon | `aarch64-apple-darwin` |
| macOS Intel | `x86_64-apple-darwin` |
| Windows x86-64 MSVC | `x86_64-pc-windows-msvc` |

Each archive is named
`norm-spec-0.1.0-rc.1-<rust-target>.tar.gz` and has a sibling `.sha256` file.
It contains both executables, the exact contract bundle, canonical Skill,
license, bilingual README, and `release-manifest.json`. The manifest binds the
archive to the tagged source revision. Follow `docs/INSTALLATION.md` and verify
the checksum, extracted manifest, compatibility response, and complete
conformance report before installation.

The SHA-256 file detects changed transport bytes; it is not a publisher
signature. This RC does not claim code signing, macOS notarization, Linux
ARM64, musl or older-glibc compatibility, Windows ARM64, package-manager
formulae, or container images.

## Installation after publication

Install both CLI executables from crates.io with an exact reviewed version:

```bash
cargo install norm-spec-cli --version '=0.1.0-rc.1' --locked
norm --version
norm compatibility --pretty
```

Rust consumers normally use the high-level facade:

```toml
[dependencies]
norm-spec = "=0.1.0-rc.1"
```

The first crates.io publication was performed serially: `norm-spec-core`, then
`norm-spec`, then `norm-spec-cli`, with exact public-index resolution and a new
dry-run between uploads.

For assisted adoption, install the complete `skills/norm-spec/` directory from
the same verified archive as the engine. Do not mix Skill files or binaries
from different candidates.

## Pre-stable boundaries

This is a release candidate, not stable `v0.1.0`. The A1 format and frozen CLI
suite are explicit and testable; the public GitHub, crates.io, docs.rs, archive
download, registry consumer, and external-install paths have all been
exercised. Correct RC publications are immutable; a defect is repaired forward
in `v0.1.0-rc.N+1` rather than overwriting an existing version.

Stable promotion requires the complete public validation record in
`docs/planning/v0.1.0-rc.1-release.md` and separate maintainer authorization.

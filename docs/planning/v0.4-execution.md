# v0.4 Rust Rewrite Execution Plan

Goal: ship a portable Rust replacement for the legacy Python runtime while
preserving the released A1 format and making machine contracts explicit.

## Gate A — Bootstrap

- [x] Establish repository governance and documentation ownership.
- [x] Record the Rust rewrite and thin-adapter decisions.
- [x] Define workspace crate boundaries.
- [x] Seed language-neutral contract fixtures.
- [x] Add local and CI quality gates.

## Gate B — Contract capture

- [ ] Inventory all five legacy CLI commands and flags.
- [ ] Capture success output, error output, exit codes, and path semantics.
- [ ] Cover BOM, leading blanks, malformed fences, legacy format, unknown keys,
      profiles, semantic errors, symlinks, and outside-root paths.
- [ ] Normalize host-specific paths without weakening meaningful order.

## Gate C — Core port

- [ ] Implement A1 and explicitly supported legacy parsing.
- [ ] Implement versioned parse and collect response models.
- [ ] Implement Draft 7 schema validation without degraded fallback.
- [ ] Implement profile and semantic rules.
- [ ] Implement deterministic structural scan and template init.

## Gate D — Consumer integration

- [ ] Publish or pin `norm-core` for sibling development.
- [ ] Make `pi-norm-spec` use the Rust engine through its bridge.
- [ ] Verify injection and enforcement end to end in pi.
- [ ] Remove the TypeScript parser/collect fallback after binary distribution
      is reliable.

## Gate E — Release and cutover

- [ ] Build and test Linux, macOS, and Windows artifacts.
- [ ] Define and verify MSRV.
- [ ] Run scope, docs, behavior, packaging, and migration review.
- [ ] Release `v0.4.0` from `main`.
- [ ] Archive the Python implementation as read-only migration history.

## Human checkpoints

Dependency selection, intentional behavior changes, public alpha publication,
and final canonical cutover require maintainer approval.

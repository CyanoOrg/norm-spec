# v0.1.0 Stable Promotion Checklist

Planning input drafted 2026-09-03. Expands the stable promotion criteria
at the end of `docs/planning/v0.1.0-rc.1-release.md` and the RC soak gate
in `ROADMAP.md` into an executable checklist. Promotion itself remains a
separate maintainer decision; nothing here changes code.

## Objective

Promote the published `v0.1.0-rc.1` line to stable `v0.1.0`: a fresh
exact stable commit, complete hosted run, four stable-version archives,
changelog, annotated tag, GitHub Release, and serial crates.io
publication under the same identity rules. No new feature scope in the
promotion diff.

## Gate 0 — RC soak (blocking)

- [ ] Two independent downstream adapters consume `0.1.0-rc.1` in
      published releases:
  - [x] dsh-norm-spec `0.1.0` stable (2026-08-18; first leg; its
        post-0.1.0 `fix/target-context` branch additionally exercised
        collect and scan payloads against the sealed rc.1 runtime
        without upstream changes).
  - [ ] pi-norm-spec first public beta (second leg; decoupled track
        per D013; readiness plan in pi-norm-spec
        `docs/planning/beta1-readiness-plan.md`).
- [ ] Soak window elapsed after the second leg ships. Duration:
      maintainer-set at scheduling; the criterion is real use, not
      idle time.
- [ ] No unresolved format, engine, CLI, package, artifact,
      installation, or Skill blocker found during RC use. Any such fix
      is published as another RC and revalidated first.
- [ ] Every Phase 7 public path from the RC run is still green
      (binary, Rust, conformance, Skill).

## Gate 1 — Promotion scope freeze

- [ ] The promotion diff contains docs and version bookkeeping only.
- [ ] `docs/decisions.md` records no decision that changes the released
      contract; post-stable work is explicitly parked (D020 collect/v2
      per `docs/planning/batch-collect-proposal.md`, case matrix in
      `docs/planning/collect-v2-contract-cases.md`).

## Phase 1 — Prepare the exact stable commit

- [ ] Branch `release/v0.1.0` from current `main`.
- [ ] Set the workspace version to `0.1.0` (three crates +
      `Cargo.lock`).
- [ ] Promote `[Unreleased]` in `CHANGELOG.md` to `[0.1.0]` with the
      release date; nothing else enters the changelog.
- [ ] Confirm `docs/SPEC.md`, `schema/`, templates, and the contract
      fixtures are unchanged from `v0.1.0-rc.1`.
- [ ] One signed commit, one semantic change, explicit staging.

## Phase 2 — Local verification

- [ ] `cargo fmt --check`.
- [ ] `cargo clippy --workspace --all-targets --all-features -- -D warnings`.
- [ ] `cargo test --workspace --all-features` — 82/82 frozen cases and
      the static requirement/case inventory gate.
- [ ] `cargo doc --workspace --no-deps` with warnings denied.
- [ ] `cargo package --workspace`.
- [ ] Self-checks: `validate --all --strict`, `scan`, `compatibility`.
- [ ] `scripts/check-contract-bundle.sh`, `scripts/check-packages.sh`,
      `scripts/check-standalone-adoption.sh`,
      `scripts/check-public-history.sh`.
- [ ] `scripts/build-release-archive.sh` for the local host target and
      `scripts/check-release-archive.sh` against the exact revision.

## Phase 3 — Hosted candidate handoff

- [ ] Push the preparation branch and open the exact-candidate PR.
- [ ] The exact nine strict `main-quality` contexts are green for the
      candidate HEAD (quality, MSRV lane, cross-platform, candidates).
- [ ] Four stable-version archives with checksum sidecars: Linux x64,
      macOS arm64, macOS x64, Windows x64.

## Phase 4 — Maintainer promotion checkpoint

- [ ] PR approved, all review threads resolved, branch not behind
      `main`; a release manager fast-forwards the exact commit (D018
      exact-promotion model, no rewrite).
- [ ] Read back that the promoted `main` HEAD equals the audited
      candidate commit.

## Phase 5 — Publication

- [ ] Signed annotated tag `v0.1.0` on the promoted commit.
- [ ] GitHub Release (full release, not pre-release) with the four
      archives and checksum sidecars bound to the tag revision.
- [ ] crates.io serial publication: `norm-spec-core`, `norm-spec`,
      `norm-spec-cli` — same identity rules as rc.1.
- [ ] Skill path re-verified from the published tag.

## Phase 6 — Public validation and wrap-up

- [ ] Fresh isolated verification of every public path: binary
      archive, `cargo install`, conformance runner, Skill consumption.
- [ ] Registry readback: all three crates report `0.1.0` as latest.
- [ ] Update the `docs/planning/status.md` resume point and record the
      promotion in the decision-free ledger of this checklist.
- [ ] Only after this phase opens the post-stable line: D020
      collect/v2 implementation order (decision → protocol identifier
      → contract fixtures → engine → facade/CLI → docs → changelog).

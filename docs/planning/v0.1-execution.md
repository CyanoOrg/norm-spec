# v0.1 Initial Rust Release Execution Plan

Goal: ship a self-contained `.norm` specification, Rust semantic engine, and
portable CLI while making format and machine contracts explicit.

## Gate A — Bootstrap

- [x] Establish repository governance and documentation ownership.
- [x] Record the single-engine and thin-adapter decisions.
- [x] Define workspace crate boundaries.
- [x] Seed language-neutral A1 contract fixtures.
- [x] Add local and CI quality gates.
- [x] Establish the independent public `0.1` product line.

## Gate B — Contract definition

The frozen record is `docs/planning/gate-b-contract.md`. It grounds the
contract in the A1 baseline captured from the private Python prototype (D002,
reference only) and records intentional deviations in D006–D008.

- [x] Freeze the five initial CLI commands (`parse`, `collect`, `validate`,
      `init`, `scan`) in one pass: flags, versioned stdout machine envelopes
      (`norm-spec/parse/v1`, `norm-spec/collect/v1`, `norm-spec/validate/v1`,
      `norm-spec/init/v1`, `norm-spec/scan/v1`, `norm-spec/error/v1`), output
      modes, stderr, exit codes, and stable error codes. Normalized exit codes:
      `0` success, `1` input/data/validation/operation failure, `2` usage,
      configuration, or root-containment failure (D006).
- [x] Inventory the five initial CLI commands and flags, including
      `--schema-dir` / `--json` (validate) and `--force` / `--json` (init).
- [x] Capture success output, error output, exit codes, and path semantics.
      Output paths are relative to the relevant root (D006).
- [x] Cover BOM, leading blanks, malformed fences, pre-A1 compatibility input,
      unknown keys, profiles, semantic errors, symlinks, and outside-root paths.
- [x] Normalize host-specific paths without weakening meaningful order.
- [x] Define canonical containment, directory-link reporting, and `.norm`
      symlink rejection (D007).
- [x] Seed one statically checked success contract for each command and one
      `norm-spec/error/v1` failure contract.
- [x] Complete `tests/contract/manifest.tsv` and expected results for every
      cross-cutting case. Static contract integrity runs in Gate B; executable
      command assertions land with each implementation slice in Gate C. A
      missing fixture, expected file, or applicable runner must fail, not skip.

## Gate C — Core implementation

- [x] Implement A1 and explicitly supported compatibility parsing.
- [x] Implement the versioned parse response and common error models.
- [x] Execute all frozen global and parse cases against the compiled binary in
      isolated roots; applicable cases fail rather than skip.
- [x] Implement deterministic root-contained collection, the versioned collect
      response model, and all 11 executable collect contract cases.
- [x] Implement Draft 7 schema validation without degraded fallback.
- [x] Implement profile and semantic rules, plus all 35 executable validate
      contract cases.
- [x] Implement deterministic structural scan and template init, plus all 19
      executable init/scan contract cases.

## Gate D — Integration readiness

- [x] Decide standalone-first product and canonical Skill ownership (D013).
- [x] Select and record a packageable high-level Rust consumer surface after a
      bounded facade-layout spike.
- [x] Verify the core, facade, and CLI workspace package candidate, and prove
      the Rust surface from an exact-revision Git dependency in an unrelated
      Cargo project without a sibling path dependency.
- [x] Publish versioned product, format, Rust API, machine protocol, and
      conformance compatibility metadata.
- [x] Provide a cross-platform consumer-neutral conformance entry point over
      the frozen fixture set with no skip state.
- [x] Exercise scan, init, collect, validation, and stable failure behavior in
      an isolated standalone project without an agent plugin or source checkout.
- [x] Ship and validate one canonical framework-neutral `norm-spec` Skill that
      invokes the versioned engine and has no parser/collect fallback.
- [x] Validate this repository with its own Rust CLI.
- [x] Verify the final integrated Gate D candidate on hosted quality, Linux,
      macOS, and Windows CI and complete one real non-plugin Skill adoption.

The detailed design, implementation batches, evidence requirements, and human
checkpoints are in `docs/planning/gate-d-design.md`.

## Gate E — Distribution and release

- [x] Build and test Linux x64, macOS Apple Silicon/Intel, and Windows x64
      artifacts locally where native and on their four native hosted runners.
- [x] Define and verify Rust 1.97 as the MSRV locally and in the dedicated
      hosted lane.
- [x] Run the local scope, docs, behavior, packaging, and compatibility review;
      confirm the integrated candidate across all hosted jobs.
- [x] Complete installation and upgrade documentation.
- [ ] Release `v0.1.0` from `main`.

The artifact contract, four native targets, MSRV policy, implementation
batches, evidence requirements, and publication checkpoints are in
`docs/planning/gate-e-design.md` (D016).

## Human checkpoints

Dependency selection, intentional behavior changes, public alpha publication,
and stable release require maintainer approval.

# v0.1 Initial Rust Release Execution Plan

Goal: ship a self-contained `.norm` specification, Rust semantic engine, and
portable CLI while making format and machine contracts explicit.

## Gate A — Bootstrap

- [x] Establish repository governance and documentation ownership.
- [x] Record the single-engine and thin-adapter decisions.
- [x] Define workspace crate boundaries.
- [x] Seed language-neutral A1 contract fixtures.
- [x] Add local and CI quality gates.
- [x] Establish the independent public `0.1` product line.

## Gate B — Contract definition

- [ ] Freeze the five initial CLI commands (`parse`, `collect`, `validate`,
      `init`, `scan`) in one pass. The contract captures flags, versioned stdout
      machine envelopes (`norm-spec/parse/v1`, `norm-spec/collect/v1`, ...),
      stderr, exit codes, and the cross-cutting cases below. The runner is part
      of the gate: a missing fixture or unavailable runner must fail, not skip.
- [ ] Inventory the five initial CLI commands and flags.
- [ ] Capture success output, error output, exit codes, and path semantics.
- [ ] Cover BOM, leading blanks, malformed fences, pre-A1 compatibility input,
      unknown keys, profiles, semantic errors, symlinks, and outside-root paths.
- [ ] Normalize host-specific paths without weakening meaningful order.

## Gate C — Core implementation

- [ ] Implement A1 and explicitly supported compatibility parsing.
- [ ] Implement versioned parse and collect response models.
- [ ] Implement Draft 7 schema validation without degraded fallback.
- [ ] Implement profile and semantic rules.
- [ ] Implement deterministic structural scan and template init.

## Gate D — Consumer integration

- [ ] Publish or pin `norm-core` for sibling development.
- [ ] Make `pi-norm-spec` use the Rust engine through its bridge.
- [ ] Verify injection and enforcement end to end in pi.
- [ ] Validate this repository with its own Rust CLI.

## Gate E — Distribution and release

- [ ] Build and test Linux, macOS, and Windows artifacts.
- [ ] Define and verify MSRV.
- [ ] Run scope, docs, behavior, packaging, and compatibility review.
- [ ] Complete installation and upgrade documentation.
- [ ] Release `v0.1.0` from `main`.

## Human checkpoints

Dependency selection, intentional behavior changes, public alpha publication,
and stable release require maintainer approval.
